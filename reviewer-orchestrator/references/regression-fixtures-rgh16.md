## AC-3: Producer-reply emitted without operator hand-writing

**Behavioral scenario — verify by running the orchestrator on a real or synthetic producer:**

1. **Setup:** A producer chat has posted a `ready-for-review` event-log row.
2. **Trigger:** Operator says "review what's ready" to the orchestrator.
3. **Expected behavior (Steps 2→9):**
   - Step 2: deterministic pre-checks run
   - Steps 3-6: CR allocation + dispatch plan + operator approval + reviewer dispatch
   - Step 7: results collected
   - Step 9: **producer-reply auto-generated** with:
     - Reply file written to `.review-gate/state/reply-<session>-<timestamp>.md`
     - `handoff-back` event-log row appended
     - Inline rendering in the orchestrator session
   - The operator did NOT write any part of the reply — it was generated by the orchestrator

**Verification checklist:**
- [ ] Reply file exists at `.review-gate/state/reply-<producer_session>-*.md`
- [ ] Reply contains: verdict, findings table (source/severity/what/where/fix), deterministic pre-check summary, next-action section
- [ ] `handoff-back` event-log row exists with `payload_ref` pointing to the reply file
- [ ] Operator's only actions were: triggering the orchestrator + approving the dispatch plan (Step 5)

## AC-4: Side-effectful items draft-not-auto-apply

**Behavioral scenario — verify by running the orchestrator on a BLOCKING review:**

1. **Setup:** A producer chat has posted `ready-for-review`. The review will find BLOCKING issues.
2. **Trigger:** Orchestrator runs, reviewer returns BLOCKING.
3. **Expected behavior (Step 8):**
   - BLOCKING verdict surfaced to operator with catches
   - Operator asked to ratify or override — orchestrator WAITS
   - The following are NOT auto-applied:
     - No handoff `status:` flip (e.g., `consumed` not written)
     - No tracker row move (Active → _recently-closed not done)
     - No CG-register entry written (if a capability gap was found, it's DRAFTED but not written)
   - The producer-reply (Step 9) includes "recommended actions" but labels them as requiring producer/operator action

**Verification checklist:**
- [ ] Orchestrator pauses after Step 8 and waits for operator input
- [ ] No writes to `_active-chats-tracker.md` by the orchestrator
- [ ] No writes to `_capability-gap-register.md` by the orchestrator
- [ ] No writes to handoff frontmatter by the orchestrator
- [ ] Producer-reply "Next action" section says "Fix the N blocking finding(s)" — does NOT say "fixed" or "applied"
- [ ] If a CG decision exists in the findings, the reply includes a DRAFT CG-register entry prefixed with "DRAFT — requires operator confirmation"
